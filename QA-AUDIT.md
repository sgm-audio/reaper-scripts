## Verified defects and fixes

### High: transient detection read only one frame

`phase-alignment-tool.lua` interpreted `GetAudioAccessorSamples` as a frame
count. The official API returns **1 for audio, 0 for no audio, -1 for an error**.
Consequently successful reads examined frame zero only, silently missing later
attacks. The detector now checks the status and examines the requested frame
count across all interleaved channels. It reads from the accessor's start,
limits analysis to its end, guards missing source/accessor and empty spans,
and releases accessors on normal success/no-audio/error paths.

New contract tests place a negative transient at frame 40 in the last channel
of mono, stereo, and four-channel buffers, while returning the documented
status 1. They also test status 0/-1, accessor creation failure, empty spans,
read boundaries, and accessor destruction. These would catch the old defect;
load-only smoke tests did not.

### High: four menus dispatched the wrong action

`gfx.showmenu` uses one-based menu item indices. The control hub, session
builder, phase tool, and plugin wrapper each prepended an ordinary selectable
title but dispatched index 1 as the first action. Clicking an action therefore
ran the next action (and the last action was unreachable). Titles have been
removed from the menu strings, making the existing action indices correct.
Tests inspect all four first rows and execute phase-tool row 6, confirming a
rightward 0.1 ms nudge and a balanced undo block. These are targeted checks,
not execution coverage of every menu branch.

### Medium: misleading timing result

The item-position comparison called a <0.2 ms difference “sample-accurate”
and suggested good mono compatibility without inspecting audio. That result
now describes item positions and explicitly says they do not establish phase
or mono compatibility. This tool remains onset/timing alignment, not a true
waveform cross-correlation or polarity analysis tool.

### QA gap: timeouts were successful skips

Lua smoke CI previously accepted timeouts as skips. Timeouts now fail CI,
and the new API contracts run alongside the existing regression suite.

## Remaining risks / manual acceptance required

- No interactive REAPER instance was available. Confirm menu labels/actions,
  undo, accessor timing on offset/rate-adjusted takes, actual FX loading,
  automation, and routing with real media before production use.
- Alignment examines only the first item on each track and only the first
  100 ms. It is threshold-based, not general phase correction. Multi-track
  alignment still lacks a separate pre-edit confirmation; review that safety
  gap before using on valuable sessions (undo is provided).
- The Python AAF interface assumes REAPER injects `RPR_*` globals; the official
  Python guidance calls for explicitly importing the REAPER module. Its
  in-host entrypoint and optional pyaaf2 processing were not exercised here.
- The AAF volume-envelope adapter hard-codes scaling mode 1 rather than
  querying the envelope mode. Its correctness on differing envelope settings
  still needs targeted investigation and tests.
- Native JUCE sources were not changed, built, or tested in this pass. Existing
  cross-platform plugin CI is separate evidence, not a local result.
- No heavy Demucs inference, model download, audio-quality listening test,
  or Windows/macOS host testing was performed. Lightweight backend tests use
  fixtures and do not establish stem quality.
